## Что проверено

- Все семь миграций применились к новой PostgreSQL БД; повторный upgrade head успешен.
  Вершина — `0007_summaries`; таблицы моделей, внешние ключи и ограничения диапазонов присутствуют.
- Vite выдаёт страницу и восстановленный main.tsx; proxy передаёт health и API-запросы.
- Регистрация, подтверждение email, отказ до подтверждения, одноразовость токена, вход и logout.
- Сброс пароля, аннулирование прежней сессии и одноразовость reset-токена.
- Серверная проверка admin-роли, блокировка пользователя и недействительность его сессии.
- TXT, PDF с текстовым слоем, EPUB, DOCX и FB2 импортируются через настоящий HTTP endpoint;
  текст доступен через читалку. EPUB-script не попадает в текст.
- Другой пользователь не получает приватную книгу, её текст, резюме и задачу.
- Прогресс чтения сохраняется; устаревшая revision отклоняется.
- Два пользователя используют одну публичную демо-версию; удаление одной связи не мешает другому читать.
- Настоящий Celery worker выполняет mock-pipeline и публикует short/medium/detailed резюме.
  Повторный idempotency_key возвращает ту же задачу. Проверены source spans, provenance,
  отдельные проверки резюме и usage events.
- ZIP с path traversal отклоняется без добавления записи библиотеки.

## Ограничения

Это регрессия основного восстановленного сценария, а не замена всех утраченных исторических тестов.
Не проверены: сборка новых Dockerfile, browser e2e/адаптивность, внешние источники,
реальные AI/TTS-провайдеры, технический fallback/retries/квоты во всех вариантах,
полная приёмка всех фаз и восстановление аварийного дампа в отдельную БД.
Публичный deployment не выполнялся. Фаза 7 ещё не реализована.
Полный аварийный архив с образами/данными по-прежнему хранится только в облаке;
пользователь подтвердил независимую копию первоначального компактного пакета исходников.

## Повторение

```bash
python scripts/validate_recovery.py
```

Нужны локальный Docker daemon и четыре существующих образа, перечисленные в README.
Интеграционные тесты требуют флаг KNIGOSKOP_VALIDATION=1 и проверяют имя/host тестовой БД,
отсутствие ключей и исключительно mock-провайдеры до выполнения сценариев.
Обычный GitHub CI запускает backend/tests и frontend-проверки; этот Docker-протокол запускался локально.
