## Что реализовано

- `/admin`: отдельные разделы пользователей, статистики, провайдеров, моделей,
  маршрутов, промптов, TTS, лимитов, источников, задач, запросов, аудита и диагностики.
  Запросы к данным раздела выполняются при его открытии. Обычный пользователь
  не получает панель; сервер независимо проверяет admin-role на каждом endpoint.
- AI-провайдеры: создание, просмотр, редактирование имени/URL, архивирование,
  восстановление, зашифрованная замена ключа. Изменение домена или протокола
  требует нового провайдера, чтобы прежний ключ не ушёл другому получателю.
- Модели: создание, редактирование контекста/идентификатора/тарифа, архивирование,
  восстановление. Архивирование — логическое удаление: ID и история остаются в БД.
  Тарифы хранятся в micro-units с валютой. Пустой тариф означает неизвестную стоимость.
- Маршруты AI: основная/резервная модель, попытки, задержка, token cap и бюджет.
  Сохранение создаёт новую версию; принятые задачи сохраняют снимок прежних настроек.
  Селекторы AI загружают все страницы (защитный предел 10 000 записей с явной ошибкой).
- TTS: создание профилей, включение/отключение, ввод/замена ключа с шифрованием,
  отдельный версионированный маршрут основного и резервного профиля.
  Основной предлагается по умолчанию; личный выбор сохраняется.
  Серверный резерв выбирается вручную, Web Speech остаётся браузерным fallback.
  После неизвестного списания автоматический платный повтор не выполняется.
- Каталог голосов GenVoice можно запросить с ключом из окружения или явным
  временным ключом администратора. Запрос каталога не выполняет синтез.
  В этой работе реальный каталог и платные провайдеры не вызывались.
- Промпты: существующие версии, тест, публикация и откат доступны из отдельного раздела.
  Управление пользователями и блокировка сохранены.
- Лимиты: общие значения и персональные исключения; удаление исключения возвращает общий лимит.
  Включены jobs/requests/input chars/tokens/active jobs/TTS chars, книги и файловое место.
- Источники: создание, редактирование, включение/отключение, paginated list,
  разрешения на конкретные издания с checksum/fingerprint/правовым основанием.
  Включение каталога не означает разрешение импортировать каждую книгу.
- Задачи: пагинация, фильтр статуса/ошибок/пользователя, отмена администратором
  с явным подтверждением в UI и аудитом. Отмена не возвращает списания провайдера.
- Статистика за 1–90 дней, фильтр пользователя: статусы задач, LLM calls/tokens,
  средняя задержка LLM, TTS calls/chars/duration, вызовы по моделям/профилям.
  Стоимость группируется отдельно по валютам; неизвестные суммы имеют отдельный счётчик.
  Это оценка по сохранённым тарифам, а не выписка провайдера и не бюджетный ledger.
- Журналы запросов LLM/TTS и аудит с пагинацией. Admin job endpoints возвращают
  только служебные поля; `result`, `snapshot`, приватные тексты и ключи исключены.
  Usage units ограничены числовыми счётчиками, без произвольных полей upstream.
  Audit содержит время, actor/action/entity IDs, без значений ключей и текстов.

## Ключи через админку

Нужен валидный серверный Fernet `AI_MASTER_KEY`, заданный вне Git.
При его отсутствии приложение работает, но сохранить зашифрованный ключ нельзя:
операция отклоняется безопасной ошибкой, интерфейс объясняет причину.
Существующий master key нельзя менять без миграции ciphertext.
Ключи не возвращаются в API и не сохраняются в localStorage; password-поля очищаются
после успешного сохранения (для AI также при ошибке). Привязки окружения сохранены.
Имена/URL/ключи не выводятся из тела ошибок validation; исключения логируются по типу.

Публичный HTTPS, постоянная доставка email и эксплуатационная настройка относятся к фазе 9.
Ввод реального ключа в опубликованную админку здесь не проверен — приложение ещё не опубликовано.

## Файловые квоты и миграция

`0009_admin`: размеры TextVersion/AudioSegment, время AudioUsage, таблица TTS-маршрутов,
индексы времени usage/audit. Миграция применялась только к новой изолированной БД.
Все девять миграций и повторный upgrade head прошли.

Квота файлов учитывает оригинал + нормализованный файл + сохранённые сегменты аудио.
Общая книга физически не дублируется, но её размер логически учитывается у каждой библиотеки.
Лимит книг проверяется при новой связи, повторное добавление существующей связи идемпотентно.
При отказе импорта временные файлы удаляются откатом. Для TTS до запуска требуется запас
на максимальный размер одного сегмента; перед записью проверяется фактический размер
под блокировкой владельца. Это консервативная проверка, не прогноз размера всей озвучки.
Изменение лимита/конкурентные задачи могут прервать многошаговую озвучку; неизвестные расходы
не выдаются за нулевые и не вызывают автоматический платный retry.

У старых файлов размер после миграции остаётся неизвестным, не считается нулём.
Новые импорты/TTS для такой библиотеки требуют предварительного учёта. Подготовлена CLI:

```bash
# Только после применения миграций в отдельно подготовленной среде:
PYTHONPATH=backend .venv/bin/python -m app.domains.admin.cli storage-accounting
# Явно записать измеренные размеры в БД:
PYTHONPATH=backend .venv/bin/python -m app.domains.admin.cli storage-accounting --apply
```

По умолчанию CLI только проверяет размеры; содержимое файлов не читает, ничего не удаляет.
Если файл недоступен, запись размеров не выполняется. `--apply` меняет только метаданные
и записывает аудит; его запуск на действующей среде требует отдельного подтверждения.
Ни одна из этих команд на действующей среде в этой работе не выполнялась.

## Сохранность и границы

Исходные контейнеры: ID/image/StartedAt/Running совпали до/после проверки.
Не было pull/build, перезапуска действующих контейнеров, миграций действующей БД,

Архивирование сохраняет историю; статистика по удалённым аккаунтам/книгам следует существующим
CASCADE-правилам и не является вечным финансовым журналом.
TTS UI/маршруты пока показывают до 100 профилей/последних версий; это ограничение MVP.

Критерии фазы 8 подтверждены бесплатными проверками. Реальные GenVoice/Yandex,
публичное размещение, SMTP/HTTPS, эксплуатационные backup/restore и полная итоговая
приёмка остаются отдельными задачами фаз 9–10; не заявляются выполненными.
Свежий ручной экспорт содержит исходники/документы/тесты, без .env, ключей, данных и образов.
Его независимое сохранение на Windows требует подтверждения пользователя.
Полный аварийный архив с БД/образами по-прежнему cloud-only; независимое хранение не подтверждено.
