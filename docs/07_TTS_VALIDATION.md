# Фаза 7: TTS, плеер и проверка

12 октября 2026. Основа: `1866c036cbe4ea74552986b8f12e7014be6f5e0a`.
Обязательные требования: FR-07 ТЗ и фаза 7 плана. Фаза 8 не начата.
Реализация и бесплатные проверки завершены; реальные провайдеры требуют отдельной проверки.

## Результат

- Миграция `0008_audio`: профили, ассеты, сегменты, прогресс, настройки голоса, usage.
- Генерация выбранного резюме/поддерева по запросу через durable outbox/Celery.
  Сегменты обрабатываются последовательно, готовые не синтезируются повторно.
  Идемпотентность, приватный кэш, квота символов, предварительная оценка бюджета.
  После неизвестного исхода внешнего вызова автоматического платного повтора нет.
- Аудиоманифест, проверка SHA-256, GET/HEAD/Range, ACL владельца на каждом endpoint.
  Удаление книги удаляет связанные аудиофайлы; другой пользователь не получает аудио.
- Плеер: play/pause, скорость 0,75–2×, перемотка, переход по словам с проверенными метками,
  автопрокрутка, сохранение позиции/скорости с revision, восстановление голоса.
  Синхронизация основана на `HTMLMediaElement.currentTime`, включая изменение скорости.
- Web Speech API включается пользователем после согласия. Используются настоящие boundary-события;
  наличие голосов и точность этих событий зависят от браузера. Облачный прогресс этого режима
  не гарантируется. Автоматического платного переключения между провайдерами нет.

## Провайдеры

GenVoice: `https://api.genvoice.ru/v1`, Bearer key,
`POST /api/tts`, JSON `text`, `voice_id` (UUID), `output_format=wav_24000`.
Возвращается WAV. Точные метки слов этот адаптер не получает.
Документация: [синтез](https://docs.genvoice.ru/operations/synthesize_speech_api_tts_post),
[quickstart](https://docs.genvoice.ru/quickstart).

Каталог голосов: `GET /api/voices/public`. Админская кнопка и защищённый
`GET /api/v1/admin/audio/voices/genvoice` возвращают только UUID/имя.
Можно получить список до создания профиля. CLI без БД:

```bash
PYTHONPATH=backend .venv/bin/python -m app.domains.audio.cli voices-genvoice
```

Yandex SpeechKit v1: `https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize`,
Api-Key сервисного аккаунта, form body, LPCM 16 kHz преобразуется в WAV.
Это отдельный выбираемый профиль, не автоматический retry. IAM-token и v3 в этой версии
не поддерживаются. Контракт проверен с подменённым транспортом; реальная совместимость,
права аккаунта, доступные голоса и тариф ещё не проверены.

Если проверенных меток нет, плеер показывает явное сообщение без точной подсветки.
Выравнивание сторонним сервисом и выдуманные таймкоды не используются (допустимо по FR-07).
Mock-профиль создаёт только сигналы с известными метками; интерфейс явно отличает их от речи.

## Проверки

- Backend: 46 unit/boundary tests; Ruff check и format.
- Интеграция: 17 tests на PostgreSQL 17, Redis, настоящих HTTP endpoints и Celery worker.
  Успешный запуск `20261012T181134Z-cb2a1c`. Все восемь миграций применены только к новой БД.
  Проверены multisegment mock-аудио, кэш/идемпотентность, bytes Range,
  межпользовательский доступ, конфликт revision и удаление.
- Frontend: 39 tests, ESLint, TypeScript и Vite build.
- Реальный Chromium 154: декодирование WAV, настоящее время media-element,
  скорость 1×/1,5×, переход вперёд/назад по словам с изменением подсветки.
  Browser fixture использует синтетический WAV и подменённые API-ответы;
  это не полный браузерный E2E регистрации/облачного синтеза.

Команды: `.venv/bin/pytest backend/tests -q`, `python scripts/validate_recovery.py`,
`npm test`, `npm run lint`, `npm run build` (из frontend),
`node scripts/audio-browser-smoke.cjs` (из корня).
Один повторный параллельный Vitest-запуск завершился двумя таймаутами прежних library-тестов.
При ограничении числа workers до одного (`npx vitest run --maxWorkers=1`), без изменения
таймаутов и assertions, все 39 тестов прошли за 12,30 секунды.
Журналы и тестовые данные находятся в игнорируемой `.cache/`; не экспортируются в Git.
Исходные контейнеры: ID, image ID, StartedAt и Running совпали до/после проверки.
Не выполнялись пересборка/скачивание образов, изменение действующей БД или платные запросы.

## Безопасное подключение и реальный тест

Пользователь согласовал отдельный суммарный лимит TTS-теста **400 RUB**, независимо от RouterAI.
Потрачено в этой работе: **0 RUB**, запросов синтеза к реальным провайдерам: **0**.
До платного вызова необходимо проверить актуальный тариф и консервативную оценку стоимости;
профильная цена — оценка, а не гарантия списания по счёту провайдера.
Начать с одного короткого синтеза после бесплатного запроса каталога голосов.
Не отправлять книги/резюме пользователя для проверки без согласия.

Требования сохранены в черновике настройки среды; сохранение черновика не активирует их:

- Секрет `KNIGOSKOP_TTS_API_KEY`, разрешённое назначение `api.genvoice.ru`.
- `TTS_ENV_PROVIDER_HOST=api.genvoice.ru`, `TTS_BASE_URL=https://api.genvoice.ru/v1`.
- Необязательный секрет `KNIGOSKOP_YANDEX_TTS_API_KEY`, назначение `tts.api.cloud.yandex.net`.
- `YANDEX_TTS_ENV_PROVIDER_HOST=tts.api.cloud.yandex.net`.

Ключи вводятся только в защищённых настройках среды. Не в чат, Git или логи.
`AI_ALLOWED_HOSTS` должен включать нужные TTS-домены с сохранением существующих разрешений.
При платформенном HTTPS-прокси требуются существующие доверенные `AI_HTTPS_PROXY`/`AI_CA_BUNDLE`;
проверку TLS отключать нельзя. Реальная доступность пока не подтверждена.

Сначала скачать и проверить свежий экспорт. Затем в настройках среды проверить/сохранить
черновик, задать секрет и опубликовать настройки. Изменение runtime/перезапуск в этой работе
не выполнялись. Запуск приложения через Compose сам по себе не наследует произвольные
секреты оболочки: текущий compose читает локальный `.env`; передачу в будущий новый стек
нужно настроить отдельно безопасным способом, не записывая значения в репозиторий.
В действующие аварийные контейнеры ключи и новый код не внедрялись.

Компактный экспорт содержит исходники, тесты и документы, но не БД/образы/тома/секреты.
Полный аварийный архив по-прежнему находится в облаке; его независимое хранение не подтверждено.
До удаления/замены среды это ограничение должно быть учтено отдельно.

## Web Speech API: дополнительная проверка 13 октября 2026

`node scripts/web-speech-browser-smoke.cjs` запускает настоящий BrowserSpeech-компонент
в отдельном Vite/Chromium с нативным speechSynthesis. Голосовой движок не подменяется;
наблюдатель событий наследует нативный SpeechSynthesisUtterance.
Проверены блокировка запуска без согласия, выбор скорости, вызов синтеза,
обработка настоящего события ошибки и отсутствие искусственной подсветки.

Chromium 154.0.8037.57 в этой облачной среде возвращает пустой список голосов и
`error: synthesis-failed`. Проверки компонента прошли, успешное произношение не подтверждено.
Слышимый звук, пауза/продолжение и boundary-события настоящего доступного голоса
в этой среде не проверены. Платные API-запросы не выполнялись.

Отдельный регрессионный тест управления с подменённым движком проверил вызовы
pause/resume/stop, сброс ошибки при повторном старте и игнорирование запоздалых
boundary-событий остановленной utterance. Исправлены сохранение прежней ошибки и
применение таких событий после stop; добавлены явные доступные имена выбора голоса/скорости.
Это тест логики интерфейса, а не доказательство реального звучания.
После исправлений: 40 frontend-тестов (7 audio), ESLint и TypeScript/Vite build.

Для ручной проверки на Windows есть `tools/web-speech-check.html`.
Скачать, открыть в Edge/Chrome, дождаться голосов, выбрать русский голос,
подтвердить согласие и нажать «Озвучить». Проверить звук, затем паузу/продолжение,
остановку и повторный запуск с 1,5×. Файл использует только Web Speech API;
это самостоятельная диагностика, не опубликованное приложение Книгоскопа.
Некоторые браузерные голоса используют сеть: тестировать только синтетическим текстом.
Отсутствие boundary-событий не должно трактоваться как точные таймкоды.

HTML-диагностика проверена через локальный HTTP: согласие и обработка нативной ошибки проходят. Открытие file:// в управляемом Chromium блокируется политикой браузера (ERR_BLOCKED_BY_ADMINISTRATOR); политика не менялась. Открытие скачанного файла на Windows требует ручной проверки пользователя.
