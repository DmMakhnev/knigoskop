# Фаза 9: результаты и границы проверки

Дата: 13.10.2026. Изменения подготовлены в `knigoskop-restored`, ветка `main`.
Публичный сервер пока отсутствует: инструкция его создания находится в
[09_STAGING_DEPLOYMENT.md](09_STAGING_DEPLOYMENT.md). Фаза 10 не начата.

## Реализовано

- Отдельный staging Compose: статический React/Caddy HTTPS, внешний пароль,
  приватные PostgreSQL/Redis, непривилегированный API/worker, ограничения RAM,
  read-only rootfs, restart policy и ротация логов. Образы имеют отдельный тег
  `phase9`; аварийные `latest` не перезаписаны.
- PostgreSQL bootstrap создаёт отдельную app-role без superuser/CREATEDB/CREATEROLE.
  Пароль администратора БД не передаётся API/worker.
- Production проверяет HTTPS, точный origin и Secure cookies. Допускается
  запуск без AI-ключей с отключёнными регистрацией и почтой. Первый admin — CLI.
- Подготовлен SMTP с TLS и контролируемыми ошибками; фактическая доставка
  требует SMTP-провайдера на VPS. Публичная настройка регистрации доступна UI.
- `/ready` проверяет PostgreSQL, Redis и `0009_admin`; `/health` — liveness.
- Maintenance backup: логический PostgreSQL dump, роли, стабильные файлы,
  приватная конфигурация, размеры/SHA-256. Проверяется `pg_restore --list`.
  Restore разрешён только в отдельный пустой project `knigoskop-restore-*`.
  Архивы защищены правами, остаются вне репозитория; Redis не восстанавливается,
  durable jobs находятся в PostgreSQL. Нельзя считать live-копию тома дампом.
- Подготовлен ежедневный systemd timer для staging. Он требует установки на
  новом VPS и согласованного окна недоступности API/worker; сейчас не включён.
- Исправлен сборщик orphan-файлов: учитывает ссылки AudioSegment, чтобы не
  удалять сохранённое аудио. На действующей среде сборщик не запускался.
- Добавлены проверки production-конфигурации, SMTP, rate limit/SSRF и защиты
  restore от traversal, абсолютных путей, symlink и изменения контрольной суммы.

## Хранение и ограничения

Приватная синтетическая тестовая копия:
`/workspace/knigoskop-staging-backups/20261013T010103Z-480da0/`.
В ней `database.dump` (95876 байт), `roles.sql` (950), `files.tar` (10240),
`environment.env` (1119), `manifest.json` (992). Полные SHA-256 находятся
в манифесте; целостность и реальное восстановление проверены. Это тестовые
данные, а не новое аварийное сохранение действующего проекта.
Независимый перенос этой копии не подтверждён.

Действующие исходные пять контейнеров имеют прежние ID, образы и StartedAt;
проверки не меняли их БД/тома. Удалены только созданные тестовые контейнеры и
их собственные временные тома. Аварийные архивы сохранены. Платных AI/TTS
запросов не выполнялось. GitHub/исходный ZIP не содержат `.env`, дампов,
книг, секретов, Docker-образов и приватных журналов.

Подготовлен исходный экспорт фазы 9; его перенос и проверка SHA-256 на Windows
потребуют подтверждения пользователя. Наличие файла в Codex само по себе не
подтверждает независимую резервную копию.

## Остаток приёмки фазы 9

Создать VPS и DNS → установить проект по инструкции → проверить публичный
сертификат и страницу с Windows → создать администратора → проверить
сквозной сценарий на настоящем staging → при необходимости подключить SMTP
и проверить письмо → проверить backup/restore и скачать копию вне сервера.
Heartbeat worker и внешний мониторинг сейчас проверяются оператором по
задачам/логам, а не отдельным readiness endpoint. Браузерная приёмка нового
публичного HTTPS стенда ещё не выполнена. До этих проверок фаза 9 полностью
не принята; дальнейшие фазы требуют отдельного разрешения.
